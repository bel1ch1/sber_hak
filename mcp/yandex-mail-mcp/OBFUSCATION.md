# Обфускация PII (persondata) в yandex-mail-mcp

Агент (LLM) **не должен видеть реальные email-адреса**. Он работает только с
обезличенными идентификаторами. Сопоставление `id → почта` живёт в CSV-датасете
**внутри MCP** и никогда не пересекает границу «MCP → агент → зарубежная нейронка».

```
            agent (LLM)                          yandex-mail-mcp                      Yandex
            только id                            граница PII                         реальная почта
  ─────────────────────────────   │   ─────────────────────────────────────   │   ──────────────
  send(to:["usr_a1b2c3"]) ───────►│──► resolveRecipients: usr_a1b2c3           │
                                   │        └─ recipients.csv → ivan@yandex.ru ─┼──► SMTP send
                                   │                                            │
  from:["usr_a1b2c3"] ◄───────────│◄── maskMessage: ivan@yandex.ru → usr_a1b2c3│◄── IMAP fetch
```

## Что видит агент

- `list_messages` / `get_message`: поля `from` / `to` / `cc` — **только id**
  (`usr_a1b2c3`, `self`, `ext_9f3a1c22`). Ни адреса, ни отображаемого имени.
- `send`: в `to` / `cc` / `bcc` агент передаёт **id**, а не адрес. Значение с `@`
  отклоняется — агент физически не может «протащить» реальный адрес.
- В ответе `send` поля `accepted` / `rejected` снова замаскированы в id.

## Три вида id

| id | Откуда | Пример |
|---|---|---|
| `usr_…` | Курируемый CSV (`recipients.csv`). Заводится вручную при онбординге. | `usr_a1b2c3` |
| `self` | Резервный id аккаунта MCP (`YANDEX_MAIL_LOGIN`). | `self` |
| `ext_<hash>` | Выдаётся на лету при первом появлении **неизвестного** адреса во входящей почте. Ссылка `token → адрес` хранится только в памяти процесса. | `ext_9f3a1c22` |

`ext_<hash>` — это усечённый SHA-256 адреса, поэтому агент не может «угадать»
валидный токен, которого он ещё не встречал в почте. Ответить на `ext_…` можно
(MCP помнит адрес), но увидеть сам адрес — нельзя.

## Онбординг нового сотрудника

Добавьте одну строку в `recipients.csv`:

```csv
id,email,label
usr_new001,ivan.novichok@yandex.ru,New hire (cohort 2026-07)
```

Выдавайте **обезличенный** id (просто набор символов, ничего не значащий).
Два новичка получают разные id и никогда не «перемешиваются». Перезапуск MCP не
обязателен только если файл читается лениво — по умолчанию датасет кэшируется на
время жизни процесса, поэтому после правок CSV перезапустите сервер.

## Конфигурация

| Переменная | По умолчанию | Значение |
|---|---|---|
| `MAIL_OBFUSCATION` | `true` | `false`/`0`/`no`/`off` — выключить (legacy: адреса как есть) |
| `RECIPIENT_DIRECTORY_CSV` | `recipients.csv` рядом с сервером | путь к CSV-датасету |

Формат CSV: `id,email,label`. Заголовок опционален; строки с `#` и пустые —
игнорируются; поля можно брать в кавычки (`"Петров, Иван"`). Колонка `label` —
заметка для мейнтейнера, агенту она не видна.

## Гарантии и границы

- ✅ Реальные адреса и отображаемые имена **не попадают** в ответы агенту.
- ✅ Отправка — только по id; неизвестный id отклоняется (письмо не уходит «в никуда»).
- ✅ Round-trip: id из входящего письма → тем же id можно ответить.
- ⚠️ Обфускация касается **адресов**. Тело письма (`text`/`subject`) не
  сканируется — если адрес/ФИО написаны внутри текста, они видны агенту.
- ⚠️ `ext_…`-карта живёт в памяти процесса (stateless HTTP — один процесс). После
  рестарта токены перевыдаются детерминированно при повторном чтении почты.
