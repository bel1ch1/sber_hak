# onboarding-mcp

MCP-сервер онбординга: **подбор бадди** + **прогресс/ворнинги новичка** с
инфографикой. Данные (сотрудники, подразделения, команды, скиллы, обязанности,
чек-листы, снапшот Jira) — мок-датасеты внутри MCP. READ-ONLY.

Вся персоналка обезличена: агент видит только id (`usr_…`), без имён и почт —
как в [yandex-mail-mcp](../yandex-mail-mcp/OBFUSCATION.md) («у бадди тоже должен
быть айдишник»).

| Инструмент | Что делает |
|---|---|
| `onboarding_list_departments` | Обзор оргструктуры: подразделения → команды → headcount |
| `onboarding_list_newbies` | Список новичков с % прогресса и числом ворнингов |
| `buddy_match` | Топ-N бадди (по умолч. 3) для новичка/роли — id + score + причины |
| `buddy_get_profile` | Обезличенный профиль сотрудника по id |
| `onboarding_progress` | Прогресс % (вехи: чек-лист + Jira) и ворнинги, JSON + markdown |
| `onboarding_dashboard_data` | Триггер «status <id>» → JSON дашборда + send_targets (HR/рук.) |
| `onboarding_probation_plan` | План на ИС: вехи + задачи ИЗ бэклога под уровень + встречи |
| `onboarding_access_request` | Шаг 1: черновик заявки на доступ руководителю (форма) |
| `onboarding_welcome_letter` | Первый этап: приветственное письмо + карта «где что» |

## Задачи из бэклога (план на ИС) + аппрув

`onboarding_probation_plan` НЕ выдумывает задачи: берёт их из мок-Jira
`data/jira_backlog.json` (заранее заполненные спринты команды по колонкам
Бэклог/В работе/В тестировании/Сделано + бэклог задач по уровням). Под уровень
и роль новичка отбираются посильные задачи (`backlog_proposal`, `needs_approval`).
Пользователь отвечает **да / нет / «все кроме SCRUM-256»** → повторный вызов с
`exclude:["SCRUM-256"]`.

## Встречи (календарь)

В плане ИС возвращается `meetings`: **1:1 с HR раз в месяц ×3**, еженедельный
синк с бадди (месяц 1), промежуточное и финальное ревью ИС. Участники — id.

## Шаг 1: доступы

`onboarding_access_request` собирает черновик «Заявки на доступ»
(`data/access_catalog.json`: общие + под роль) на согласование руководителю;
форма — `data/access_request_form.html`. Заявитель/руководитель — обезличенные id.

## Дашборд по триггеру

`onboarding_dashboard_data` — на команду «status <id>» / «статус <id>». Кроме
данных дашборда отдаёт `send_targets` (HR + руководитель) — после показа система
предлагает отправить дашборд HR, руководителю или обоим (через mail-MCP по id).

## План на испытательный срок (ИС)

Задачи в Jira **формируются из мок-шаблона** `data/probation_plan.json`, а не
выдумываются. `onboarding_probation_plan(newbie_id | role)` разворачивает шаблон
в готовый epic + список задач по месяцам ИС (m1/m2/m3): общие вехи + задачи под
роль, каждая с `ref` (ИС-01…), `acceptance` и `assignee` = обезличенный id
новичка. Агент берёт этот список и создаёт задачи через MCP Jira (пункт 7
классического процесса «Формирование плана на ИС»). Срок ИS — 3 месяца,
`probation_end` считается от `start_date`.

## Подбор бадди

`buddy_match` ранжирует кандидатов по: та же команда (+40) → то же подразделение
(+25) → та же роль (+15) → общие навыки (+6 за навык, до +24) → подходящее
старшинство (бадди на 1–2 грейда выше, +15) − загрузка ментора (−5 за подопечного).
Бадди должен быть опытнее новичка. Возвращает **обезличенные id** + причины.

## Прогресс и ворнинги

Прогресс = взвешенные вехи (сумма 100): бадди назначен (15), доступы (10),
доки (10), вводная (10), курсы назначены (10) / начаты (15), первая задача взята
в работу (15, из Jira), первая задача завершена (15, из Jira).

Ворнинги (порог грейс-периода — день 3):
- 🔴 **Бадди не назначен** (`assigned_buddy_id = null`)
- 🟠 **Курсы не начаты** (назначены, но не начаты)
- 🟠 **Не взял ни одной задачи в работу** (нет задач In Progress/Done) — из аудио
- 🟠 **Задача зависла** (In Progress > 5 дней без движения)

Источник Jira — снапшот в `data/newbies.json` (`jira.tasks`); в проде
подставляется из [jira_mcp](../hackathon/jira_mcp). Дату «сегодня» можно
зафиксировать через `ONBOARDING_TODAY`.

## Инфографика

`onboarding_dashboard_data` отдаёт JSON → страница `dashboard.html` рисует
дашборд: кольцо прогресса, статус, чек-лист, панель ворнингов, карточка бадди /
топ-3 кандидатов. **MCP считает — Artifact рисует.**

## Данные

| Файл | Что |
|---|---|
| `data/employees.json` | Сотрудники (пул бадди): id, подразделение, команда, должность, роль, старшинство, скиллы, обязанности, опыт, загрузка |
| `data/newbies.json` | Новички: роль, дата старта, бадди, назначенные курсы, чек-лист, снапшот Jira |

id совместимы с `recipients.csv` из mail-MCP (тот же человек = тот же `usr_…`).

## Локальный запуск

```bash
cd onboarding-mcp
npm install
npm run smoke      # прогон датасетов + подбор + прогресс
npm test

# HTTP :3005 (на Linux напрямую; with-ca.cmd — только Windows)
MCP_TRANSPORT=http MCP_HTTP_PORT=3005 node --import tsx server.ts --http
# curl http://localhost:3005/healthz
```

## Конфигурация

| Переменная | По умолчанию | Значение |
|---|---|---|
| `ONBOARDING_OBFUSCATION` | `true` | `false` — показывать имена/почты (admin) |
| `ONBOARDING_EMPLOYEES_PATH` | `data/employees.json` | путь к датасету сотрудников |
| `ONBOARDING_NEWBIES_PATH` | `data/newbies.json` | путь к датасету новичков |
| `ONBOARDING_TODAY` | системная дата | зафиксировать «сегодня» (YYYY-MM-DD) для демо |
