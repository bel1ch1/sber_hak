# Политика доступов

Доступы оформляются заявками в ITSM (Naumen). Часть выдаётся автоматически по
роли, критичные — только после согласования руководителя (human-in-the-loop).

## Доступы для backend-разработчика (команда «Платёжные сервисы»)
| Система | Уровень | Согласование |
|---------|---------|--------------|
| GitLab (репозитории команды) | developer | авто по роли |
| Jira (проект SCRUM) | member | авто по роли |
| Корпоративная Wiki | read | авто по роли |
| Kubernetes (namespace payments-stage) | read/deploy stage | руководитель |
| PostgreSQL (stage) | read | руководитель |
| Kafka (топики payments, stage) | read | руководитель |
| Grafana / мониторинг | viewer | авто по роли |
| Production-доступы | — | **не выдаются на испытательном сроке** |

## Правила
- Принцип наименьших привилегий. Prod — только после испытательного срока и
  отдельного обоснования.
- Каждая заявка — с указанием роли и срока. Просроченные доступы отзываются.
- Секреты — только через корпоративный vault, не в коде и не в переписке.
