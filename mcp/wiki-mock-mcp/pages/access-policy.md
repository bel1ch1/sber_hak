# Политика доступов

Доступы оформляются заявками в ITSM (Naumen). Часть выдаётся автоматически по
роли, критичные — только после согласования руководителя (human-in-the-loop).

При формировании заявки на онбординг указывай для каждого пункта: **систему**,
**уровень**, **краткое описание** (зачем доступ) и **тип согласования**.

## Общие доступы (всем сотрудникам)

| Система | Уровень | Описание | Согласование |
|---------|---------|----------|--------------|
| SSO | account | Единая учётная запись корпоративного каталога (вход во все внутренние сервисы). | авто |
| Корпоративная почта | mailbox | Ящик и календарь для рабочей переписки и приглашений. | авто |
| Corp VPN | user | Удалённый доступ во внутреннюю сеть (stage/prod-контуры, админки). Без VPN внешние сети не видят корпоративные ресурсы. | авто |
| Jira (проект SCRUM) | member | Задачи, спринты, онбординг-бэклог испытательного срока. | авто по роли |
| Confluence / Wiki | read | Регламенты, runbook’и, политики доступов и онбординга. | авто |
| Корпоративный мессенджер | member | Командные чаты (уведомления, эскалации, buddy). | авто |

|---------|---------|----------|--------------|

| CI/CD (GitLab Pipelines) | developer | Запуск/просмотр пайплайнов сборки и деплоя в stage. | авто по роли |

| PostgreSQL (stage) | read | Чтение схем и данных stage БД платёжных сервисов для отладки. | руководитель |
| Kafka (топики payments, stage) | read | Просмотр сообщений/лагов consumer’ов на stage. | руководитель |

## Ограничения

| Система / зона | Правило |
|----------------|---------|
| Production-доступы (K8s prod, БД prod, Kafka prod) | **Не выдаются на испытательном сроке** без отдельного обоснования и approve руководителя + ИБ. |
| Admin / break-glass | Только дежурные и on-call; не включать в стандартный онбординг. |
| Финансовые роли в 1С / CRM (полный write) | Только профильные сотрудники; backend по умолчанию **не** получает CRM/1С. |

## Правила оформления заявки

- Принцип наименьших привилегий. Prod — только после испытательного срока и отдельного обоснования.
- Каждая заявка — с указанием роли, команды, срока и **описания** каждого доступа (зачем).
- Просроченные доступы отзываются.
- Секреты — только через корпоративный vault, не в коде и не в переписке.
- Для backend в «Платёжных сервисах» базовый пакет = **общие доступы** + таблица backend; CRM и 1С — только по явному запросу руководителя.
