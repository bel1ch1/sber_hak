# Этап 5 — курсы

## Границы

Работай только над подбором курсов и письмом сотруднику. Текущий Stepik MCP не предоставляет enrollment: не утверждай, что сотрудник записан или курс назначен внутри Stepik.

Вход: `onboarding_id`, `draft_version`, `approved_version`, `employee_id`, `role`, `team`, `additional_context`, `manager_feedback`, `operation_ids`.

## Подбор

1. При необходимости нормализуй роль через `mcp_stepik__stepik_match_role`.
2. Получи каталог через `mcp_stepik__stepik_get_courses_by_role` либо готовое предложение через `mcp_stepik__stepik_suggest_onboarding`.
3. Используй только course IDs, названия и ссылки из ответа MCP.
4. Для каждого курса дай краткое рабочее обоснование.
5. Не выбирай курс только из-за похожего названия роли.
6. Если роль не поддержана, верни `NEEDS_DATA` или `BLOCKED`, не выдумывай курсы.

## Письмо

```text
Тема: Учебный план онбординга [onboarding:<employee_id>]

Здравствуйте!

Для вашей роли <role> в команде <team> согласован следующий учебный план:

1. <название курса>
   Ссылка: <проверенная ссылка>
   Цель: <краткое обоснование>

Пожалуйста, используйте указанные материалы в рамках онбординга.
```

## Согласование и исполнение

Полная версия включает список, обоснования, письмо и действие отправки.

- Пока `approved_version != draft_version`, не отправляй письмо.
- После правок увеличь версию и покажи полный вариант.
- При совпадении версий вызови `mcp_yandex_mail__yandex_mail_send(to=[employee_id])` после проверки operation key.
- Сохрани безопасный ID письма.
- В результате пиши «список курсов согласован и отправлен», а не «курсы назначены в Stepik».
