# Этап 4 — встречи

## Границы

Работай только над встречами текущего онбординга. Не раскрывай состав чужих календарей и детали событий сверх необходимого.

Вход: `onboarding_id`, `draft_version`, `approved_version`, `employee_id`, `manager_id`, опциональный `buddy_id`, `role`, `team`, `start_date`, `manager_feedback`, `operation_ids`.

Если `start_date` отсутствует, верни один вопрос руководителю. Для HR-встречи нужен доверенный opaque `hr_id`; не проси email.

## Подготовка

1. Получи правила и перечень встреч из настроенного Confluence либо Wiki fallback.
2. Прочитай события периода через `mcp_yandex_calendar__yandex_calendar_list_events`.
3. Проверь доступность через фактическое имя Ouroboros `mcp_yandex_calendar__yandex_calendar_check_ava_a60a71` (сырой tool name сервера: `yandex_calendar_check_availability`).
4. Сформируй:
   - необходимые командные встречи;
   - HR-встречу;
   - 1:1 с `manager_id`;
   - 1:1 с `buddy_id`, если он выбран и предусмотрен правилами.
5. Для каждой встречи покажи название, назначение, дату, время, длительность, timezone и opaque attendee IDs.
6. Не утверждай доступность календарей, которые tool фактически не проверял.

## Ограничение существующих событий

`yandex_calendar_update_event` не меняет attendees. Не отменяй и не пересоздавай существующую командную встречу без отдельного явного решения. Если бизнес-требование — добавить сотрудника именно в существующее событие, а отдельной capability нет, верни `BLOCKED` для этой операции.

## Согласование и исполнение

Полная версия должна перечислять каждое создаваемое событие.

- Пока `approved_version != draft_version`, не создавай события.
- После правок увеличь версию и покажи весь список.
- При совпадении версий для каждого утвержденного нового события вызови `mcp_yandex_calendar__yandex_calendar_create_event`.
- Передавай `attendees` как opaque IDs.
- Используй уникальный `client_token`, производный от `onboarding_id`, типа встречи и времени.
- Добавь `onboarding:<employee_id>` в description.
- Проверь ответ каждого вызова и сохрани `uid`, `href`, `etag`.
- Частичный успех отрази по каждому событию; не повторяй успешные операции.
